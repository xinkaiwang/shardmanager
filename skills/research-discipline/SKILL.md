# Research discipline

Two artifacts, two homes, one purpose: six months later, someone — probably you
— must be able to answer *what exactly produced this number, and what did we
believe before we ran it.*

| Artifact | Home | What it is |
| --- | --- | --- |
| Design doc | `docs/design/YYYY-MM-DD-<slug>.md` | A decision and its reasoning, written once, dated by when it was written |
| Investigation | `research/YYYY-MM-DD-<slug>/notes.md` | A dated write-up: numbered findings + decision log |
| Experiment | `research/YYYY-MM-DD-<slug>/expNN-<slug>/` | A runnable experiment: command, inputs, raw output, expectation |

## Design docs

`docs/design/2026-03-06-tts-cache.md` — date first, ISO, then a kebab slug.

The date prefix is the point: `ls docs/design/` is a chronological reading of
how the system's thinking evolved. Sorting by topic would hide that; sorting by
date makes "what did we believe in March" a directory listing.

The date is **when it was written**, and it does not get updated. A decision
that changes later earns a new dated doc that says what it supersedes — the old
one stays, because the reasoning that was later abandoned is exactly what stops
the same idea being re-proposed next year.

## Investigation notes

`research/YYYY-MM-DD-<slug>/notes.md`, containing:

- **Numbered findings** — a stable prefix per investigation (`KLOG-001`,
  `FTQ-003`, `XS-007`), so a finding can be cited in a commit message, a code
  comment, or a later document and still resolve years on.
- **A decision log**, including the options that were **rejected and why**. The
  rejected branch is the part that stops the discussion being re-run from
  scratch; a log of only what was chosen is a log of half the work.
- A **severity or grade only where a concrete failure scenario is written out**
  — who, in what situation, suffers what. If the consequence chain cannot be
  written, it is an observation, not a problem.

## Experiments

One folder per experiment:

```
research/2026-04-04-omlx-cache/
  exp01-baseline-no-cache/
    README.md      the record — written BEFORE the run
    run.sh         the exact command, committed, self-contained
    request.json   inputs (generated by run.sh or handwritten)
    result.log     raw output, kept verbatim
  exp02-ssd-cache/
  shared/          assets used by several experiments (prompts, bench scripts)
  experiments-summary.md   roll-up once several experiments exist
  <topic>.md               the synthesized findings
```

### The rules that make it an experiment rather than a log

**1. A changed parameter is a NEW experiment.** Different model, different
prompt size, revised command, fixed bug — new number, new folder. Never edit a
previous experiment's `run.sh` and rerun over its `result.log`. The moment you
overwrite, the earlier number becomes unattributable: it was produced by a
command that no longer exists anywhere.

**2. Write the expectation before running.** The `README.md` says what you
expect to see and why, *before* there is a result to rationalize. An experiment
whose expectation is written afterwards cannot surprise you, and being surprised
is the only thing an experiment is for.

Sections that carry their weight: **目的** (what question), **方法** (how, with
the parameters that matter spelled out — model, data size, mode), **预期** (what
you expect and why), **对比基准** (which earlier experiment this is measured
against, by ID), **运行** (the command).

**3. The command is committed and self-contained.** `run.sh` in the folder, with
its parameters visible in the file, not typed at a shell prompt and lost. If it
reads a shared asset, it reads it from `../shared/`.

**4. Raw output stays in tree.** `result.log` / `result.jsonl` / `run.log`,
verbatim. Not a summary — the summary is derived, and derivations get redone
when the question changes.

**5. IDs are never reused.** An `expNN` identifies exactly one experiment
forever. If two experiments end up with the same number, the later one takes the
next free number; a duplicated ID makes every later citation ambiguous.

**6. Slugs, not bare numbers.** `exp03-comma-normalization`, not `exp03`. A
directory listing should say what was investigated without opening six READMEs.

**7. Roll up when the set grows.** Once several experiments answer one question,
an `experiments-summary.md` or a topic document states the finding and cites the
experiment IDs that support it. The individual folders stay as evidence.

### What a good sequence looks like

```
exp17-realtime-50            baseline, one model
exp18-realtime-50-sonnet     same setup, model swapped   ← new folder, not an edit
exp19-realtime-full-sonnet   same model, full data
```

Three folders, three intact results, each citable. Had these been one folder
edited three times, the only surviving number would be the last one, and the
comparison the whole investigation existed to make would be gone.

## Naming: one date format

`YYYY-MM-DD` everywhere — design docs, research folders, experiment days. ISO
sorts correctly in every tool and matches the date the artifact records.

Older folders using other forms (`2026_0809.TopicName`) are grandfathered; do
not mass-rename working history, but write new ones the new way.
